# CodeCraftHub

CodeCraftHub is a beginner-friendly Java Spring Boot REST API for tracking courses you want to learn. It demonstrates HTTP requests, CRUD operations, request validation, and JSON file persistence without a database or user accounts.

## Features

- Create, list, retrieve, update, and delete courses.
- Store courses in `courses.json` using Jackson.
- Automatically create the storage file on the first request if it does not exist.
- Generate numeric course IDs starting at 1 and creation timestamps.
- Validate required fields, dates, and exact status values.
- Return HTTP error responses for invalid requests, missing courses, and storage failures.
- Preserve the original ID and creation time when updating a course.

This project provides a REST API; it does not include a browser user interface.

## Course JSON format

A response or saved course looks like this:

```json
{
  "id": 1,
  "name": "Python Basics",
  "description": "Learn Python fundamentals",
  "target_date": "2025-12-31",
  "status": "Not Started",
  "created_at": "2025-11-04 10:30:00"
}
```

| Field | Request rules |
|---|---|
| `id` | Generated by the server; omit from POST and PUT bodies |
| `name` | Required, must contain non-whitespace text |
| `description` | Required, must contain non-whitespace text |
| `target_date` | Required, valid date in `YYYY-MM-DD` format |
| `status` | Required, exactly `"Not Started"`, `"In Progress"`, or `"Completed"` |
| `created_at` | Generated by the server; omit from POST and PUT bodies |

Dates in the past are allowed so overdue courses can remain tracked. Creation timestamps use the server's local time in `yyyy-MM-dd HH:mm:ss` format. Name and description are trimmed before saving.

## API documentation

All request bodies use `Content-Type: application/json`. No authentication headers are needed. The examples below use a POSIX shell; on Windows, use IntelliJ's included `courses.http` file or adapt the quoting for your shell.

| Method | Endpoint | Purpose | Success |
|---|---|---|---|
| POST | `/api/courses` | Add a course | 201 Created |
| GET | `/api/courses` | List all courses | 200 OK |
| GET | `/api/courses/{id}` | Get one course | 200 OK |
| PUT | `/api/courses/{id}` | Replace editable course fields | 200 OK |
| DELETE | `/api/courses/{id}` | Delete a course | 204 No Content |

### Add a course

```bash
curl -i -X POST http://localhost:8080/api/courses \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Python Basics",
    "description": "Learn Python fundamentals",
    "target_date": "2026-12-31",
    "status": "Not Started"
  }'
```

The response contains the saved course, including its generated `id` and `created_at`. The `Location` header identifies the new resource, for example `/api/courses/1`. Use the actual returned ID in subsequent requests.

### Get all courses

```bash
curl -i http://localhost:8080/api/courses
```

Returns a JSON array of course objects. With no courses, the response body is `[]`.

### Get a specific course

```bash
curl -i http://localhost:8080/api/courses/1
```

Returns the course object, or 404 if ID 1 does not exist.

### Update a course

```bash
curl -i -X PUT http://localhost:8080/api/courses/1 \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Python Basics",
    "description": "Practice Python fundamentals and exercises",
    "target_date": "2026-12-31",
    "status": "In Progress"
  }'
```

PUT requires all four editable fields, even when changing only the status. Returns the updated object while preserving `id` and `created_at`. A missing ID returns 404.

### Delete a course

```bash
curl -i -X DELETE http://localhost:8080/api/courses/1
```

A successful deletion returns 204 with no body. Deleting an unknown ID returns 404.

### Error responses

| Status | Meaning |
|---|---|
| 400 Bad Request | Missing/blank required fields, malformed JSON, invalid date, invalid status, or nonnumeric path ID |
| 404 Not Found | No course exists with the requested ID |
| 500 Internal Server Error | Unable to read or write the JSON storage file |

Validation and storage failures return JSON problem details. A missing required field can produce a response such as:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "Required fields are missing or invalid.",
  "instance": "/api/courses",
  "errors": {
    "name": "must not be blank"
  }
}
```

## How JSON storage works

`courses.json` is a UTF-8 text file containing a JSON array. It starts with `[]`. The default path is relative to the application's working directory.

Each course operation loads the entire array from disk using Jackson's `ObjectMapper`. Create, update, and delete operations change that list and save it back with readable indentation. A missing file is initialized automatically on the first request. Invalid existing JSON raises an error and is not silently replaced.

Saving writes a temporary file beside the original, then replaces the original atomically when supported by the filesystem. Service methods are synchronized to prevent overlapping changes within one running application.

Run one application instance against a given file. This simple approach reads and rewrites the whole list and is intended for a small learning project. IDs use the highest stored ID plus one, starting at 1; deleting the highest ID allows its number to be reused later.

Back up the file before manual edits and stop the application while editing. Do not delete it unless you want to remove all saved courses.

To choose another storage file, change `courses.file` in `application.properties`, or run:

```bash
java -jar target/codecrafthub-0.0.1-SNAPSHOT.jar --courses.file=/absolute/path/courses.json
```

## Troubleshooting

| Problem | What to check or do |
|---|---|
| `java` is missing or `JAVA_HOME` is invalid | Install/select a full JDK 17–25. `JAVA_HOME` must point to the JDK folder, not its `bin` folder. |
| Compilation fails, `javac` is missing, or `release version 17 not supported` appears | Use a full JDK for both IntelliJ's Project SDK and Maven runner/importer. On this computer, use the bundled JDK path documented above. |
| `Permission denied` when running `./mvnw` | Run `chmod +x mvnw`, then retry. |
| Maven cannot download dependencies | Check internet access and proxy settings, ensure Maven is not in offline mode, then reload the Maven project. |
| Port 8080 is already in use | Stop the other application or run with `--server.port=8081`; update request URLs to use the selected port. |
| Connection refused | Start the application and wait for the startup message. Confirm the host and port match its configuration. |
| Opening `/` returns 404 | This project has no home page. Use `/api/courses`. |
| A course request returns 404 | Use an existing numeric ID returned by POST or GET. Deleted courses are no longer available. |
| A request returns 400 | Include all four editable fields, valid JSON, the JSON content type, a real date, and an exact allowed status string. PUT also requires all four fields. |
| A request returns 500 | Inspect IntelliJ's Run console or the terminal log for the underlying file error. Check storage directory permissions and available disk space. |
| The JSON file is malformed | Stop the app, back up the file, and repair its JSON array structure and field values. An empty file is invalid JSON; an empty course list is `[]`. |
| Saved courses seem to disappear or a second file appears | Check the application's working directory. Relative `courses.json` paths can resolve to different folders. Set an absolute `courses.file` path if needed. |
| `courses.json` does not exist yet | Make a GET request to `/api/courses`. Missing files are created on the first course operation. |
| IntelliJ cannot resolve Spring imports | Reload `pom.xml` from the Maven tool window and check the configured JDK and dependency download errors. |

Tests use a temporary storage directory and do not change your project's saved courses. They cover CRUD, persistence, automatic file creation, required fields, date/status validation, missing courses, and malformed-file protection.
